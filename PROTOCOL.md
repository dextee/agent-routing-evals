# Pilot protocol

Freeze the cases, expected decisions and escalation rule before the first measured request. The six development cases illustrate the policy. The 20 held-out cases are kept out of development prompts and graded after inference. Both sets are synthetic and public, so future runs on this release are regression checks, with no contamination guarantee.

Compare a fixed GPT-6 Luna batch at medium effort with the same Luna answers plus a second read by GPT-6.2 Sol at medium effort. The second read gets every case with an absent ticket reference or a raw ledger row count other than one. It sees the original cases and policy only. This input-only rule is fixed before evaluation. Use two independent repeats, retaining the baseline batch of each repeat as the first stage of its escalation route. Use a read-only, ephemeral CLI from an empty temporary directory with no case files or expected answers. Record completed model-returned JSON, wall time, CLI token usage and failed attempts. Refuse tool-using runs. If a selected stage fails, mark its cases unresolved. Report whole-route latency as the sum of stage times. No automatic retries in this pilot.

Grade a case as accepted only when its route, claim code, human-review flag and set of source IDs all match the answer key. Report missed escalations and incorrect claims separately. An unsupported summary is a valid claim code with the wrong meaning for that input. This test measures controlled claims, not unconstrained prose. The primary unit is a ticket, with two observations per ticket. Keep the same 20 cases per repeat and publish per-case outcomes. Subscription billing does not provide per-request USD. Leave cost per accepted case unknown unless actual charges for every attempt are supplied.
